# Domains are modeled by role in `src/lib/domains.ts`, not as one shared string

The obvious shortcut — `const DOMAIN = "jknm.si"` with everything else templated off it — was rejected. `jknm.si`, `jknm.org`, `jknm-si.vercel.app`, and `gradivo.jknm.org` each name a different *role* (where the app is deployed, its public SEO identity, the old site being replaced, the media CDN, the org's real mailbox, the Resend-verified sender), and those roles have independent lifecycles and owners: `DEPLOYMENT_ORIGIN` changes per environment and once at DNS cutover (Vercel-owned); `CANONICAL_ORIGIN` changes once, by hand, on cutover day; `LEGACY_SITE_ORIGIN` and `MEDIA_CDN_ORIGIN` never change regardless of the cutover (Cloudflare-owned); `MAIL_FROM_DOMAIN` changes only once Resend verifies a new sending domain. A flat `DOMAIN` constant would make an edit meant for one role silently apply to all of them — e.g. flipping the app's own origin at cutover would also rewrite the *legacy*-site matcher, breaking recognition of old pasted links.

Some of these constants hold the identical string value today (`LEGACY_SITE_ORIGIN` and `CANONICAL_ORIGIN` are both `https://www.jknm.si` pre-cutover) and will diverge or re-converge over time — that's treated as coincidence, not coupling, and is why each is its own named export rather than one derived from another.

`CANONICAL_ORIGIN` is deliberately a hand-edited code constant, not an environment variable, even though it does change: the change is a one-time calendar event (DNS cutover), not something that varies per deployment environment, so a committed code edit gives it a `git blame` record that a Vercel-dashboard env var edit would not.
